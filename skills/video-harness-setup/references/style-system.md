# 스타일 일관성 장치

채널마다 스타일 값이 한 곳에 모여 있지 않으면 회차마다 색·글꼴·모션이 흔들린다. shorts에서 실제로 그랬다: 폰트만 규칙 문서가 있어서 전 회차가 같았고, 나머지(색·이징 등)는 회차별 코드에 흩어져 있어 회차마다 달랐다. 이 스킬은 그 값을 채널 하나당 한 곳(`<채널>/03_편집프로젝트/_채널공용/`)에 모으는 장치만 설치한다. 실제 값은 세팅 때 확정하지 않는다.

## frame.md — 단일 원본

`<채널>/03_편집프로젝트/_채널공용/frame.md`는 그 채널 스타일의 단일 원본이다. YAML 머리말(frontmatter)이 규범 값이고 본문은 맥락 설명이다. HyperFrames가 원래 읽는 형식이라 별도 설정 없이도 그대로 따른다.

머리말의 `status`는 `draft` 또는 `approved`다. 세팅 직후에는 항상 `draft`다 — 레퍼런스 분석과 첫 샘플 승인을 거쳐야 `approved`로 바뀐다. `draft`인 동안은 머리말 값이 아직 확정되지 않았다는 뜻이므로, 값이 이상해 보여도 세팅 단계에서 함부로 고치지 않는다.

## 세 가지 고정 범위

`frame.md`의 `consistency` 항목이 값을 세 단계로 나눈다.

- `locked` — 모든 회차가 같다. `check_style.py`가 어긋나면 오류로 표시한다. 예: 폰트, 자막 크기와 위치, 제목바.
- `choose` — 정해 둔 후보 안에서 회차마다 고른다. 후보 밖이면 오류다. 예: 강조색 세트 중 하나, 전환 효과 중 하나.
- `free` — 회차마다 자유. 검사하지 않고 회차 문서에 기록만 한다. 예: 삽화 색, 자료화면.

**세팅 때는 성향만 정한다.** 인터뷰 3-2에서 고른 일관성 수준이 머리말의 `consistency_level`에 적히고, "포맷 고정형"(`fixed`)일 때만 이 블록이 더 좁은 기본값으로 시작한다 — 전환과 강조색이 `locked`로 올라가고 `choose`가 비고 `free`는 `["footage"]`만 남는다. 즉 포맷 고정형은 삽화 색까지 `frame.md`의 색으로 제한하니, 이야기별 삽화 색을 자유롭게 쓰려면 회차 변주형을 고른다. "회차 변주형"과 "만들면서 정함"(기본값)은 템플릿 기본 블록 그대로다. 실제로 무엇을 `locked`로 올릴지는 2단계(제작 절차 스킬)에서 첫 샘플을 승인할 때 정한다. 이후로도 `free`를 `locked`로 올리거나 그 반대로 내릴 수 있고, 바꿀 때마다 사용자 승인을 받는다. 세팅 스킬은 이 값이 나중에 바뀔 수 있는 자리와 장치만 만들어 둔다.

## 토큰 파일 — build_tokens.py

`도구/style/build_tokens.py`가 `frame.md`의 머리말을 읽어 `tokens.css`(HyperFrames, `--css`)와 `theme.ts`(Remotion, `--ts`)를 만든다. 회차 소스는 이 생성된 파일만 참조하고 값을 직접 하드코딩하지 않는다. `frame.md`를 고칠 때마다 이 도구를 다시 돌려 재생성한다. `frame.md`가 없거나 머리말이 안 닫혀 있으면 오류를 낸다.

## 폰트 — fonts 모듈

`python3 "${SKILL_DIR}/scripts/install_module.py" run "<workspace>" fonts`를 실행하면 `orioncactus/pretendard` 저장소의 최신 GitHub 릴리스를 조회해 그 안에서 `Pretendard-Bold.otf`와 `Pretendard-Medium.otf`만 꺼내 `<workspace>/스타일_라이브러리/01_폰트/`에 넣는다(다른 굵기·JP 변형 등은 무시한다). 같은 이름의 파일이 이미 있으면 절대 덮어쓰지 않는다. 네트워크가 필요하다.

Paperlogy는 자동으로 받지 않는다. 수동 확인 항목으로만 안내한다: "Paperlogy는 https://freesentation.blog/paperlogyfont 에서 받아 같은 폴더에 넣기".

폰트 파일이 채워지면 스모크 테스트가 엔진에 따라 다르게 연결한다.

- **HyperFrames**: 스모크 테스트가 `스타일_라이브러리/01_폰트/`에 `Pretendard-Bold.otf`·`Paperlogy-Black.ttf`가 있는지 확인해, 있는 파일만 회차 프로젝트의 `assets/fonts/`로 복사하고 `index.html`의 해당 `@font-face`의 `src` 맨 앞에 `url("assets/fonts/<파일명>"), `를 끼워 넣는다. 파일이 없으면 원래 있던 `local(...)` 폴백만 남아 시스템 폰트로 대체된다.
- **Remotion**: 스모크 테스트는 라이브러리 폰트를 자동으로 연결하지 않는다. 프로젝트 전용 폰트가 필요하면 회차템플릿-remotion의 `public/넣는_방법.md`가 안내하는 대로 `public/`에 파일을 넣고 `@remotion/fonts`의 `loadFont()`로 직접 로드해야 한다. 아무것도 넣지 않으면 시스템에 설치된 한글 폰트로 자동 대체된다.

어느 쪽이든 실제로 쓰이는 폰트 패밀리 이름과 굵기는 코드에 하드코딩하지 않는다. 항상 `frame.md`의 `typography` 값에서 `build_tokens.py`가 만든 `tokens.css`(`var(--f-*)`, `var(--f-*-w)`)나 `theme.ts`(`theme.typography.*Family`/`*Weight`)를 통해 가져온다. `frame.md` 값을 바꾸면 토큰 파일만 다시 만들면 되고, 폰트 파일 이름 자체는 채널·회차마다 다시 적지 않는다.

## 검증 — check_style.py

`도구/style/check_style.py`는 회차 프로젝트의 소스 파일(`.html`, `.css`, `.tsx`, `.ts`, `.jsx`, `.js`)에서 색상(`#rrggbb`)·폰트(`font-family`, JSX의 `fontFamily`)·글자 크기(`font-size`, JSX의 `fontSize`)·이징(`ease`)을 뽑아 `frame.md`의 규범 값과 대조한다.

- `typography`가 `locked`이면 토큰에 없는 폰트·크기는 **오류**다.
- `motion.in`/`motion.out`이 `locked`이면 토큰에 없는 이징은 **경고**다(설명 그래픽 고유 모션일 수 있어 무시해도 된다).
- 색은 토큰에 없으면 기본은 **오류**지만, `illustration_colors`가 `free` 목록에 있으면 **자유 기록**으로만 남긴다. 검사기는 `frame.md`가 선언한 것만 따르므로, 삽화 색을 묶고 싶으면 `free`에서 그 항목을 빼면 된다(포맷 고정형이 그렇게 시작한다).
- `accent_sets`는 `choose`에 `colors.accent`가 있을 때만 후보로 인정된다. 포맷 고정형은 `choose`가 비어 있으므로 강조색은 `colors.accent` 하나뿐이고, `accent_sets`에 색을 적어 두어도 회차에서 쓰면 오류다. 후보를 살리려면 `choose`에 `"colors.accent": "colors.accent_sets"`를 다시 넣는다.
- `tokens.css`/`theme.ts` 자기 자신은 검사 대상에서 빠진다(생성물이라서다).

## 공용 부품과 회차 템플릿

새 회차는 `_채널공용/회차템플릿/`(HyperFrames) 또는 `회차템플릿-remotion/`(Remotion)을 복사해서 시작한다. 두 엔진을 함께 골라도 `frame.md`는 하나뿐이다.

제목바·말자막·출처표기는 **지금 회차템플릿 안에** 들어 있다 — HyperFrames는 `index.html`의 `#title-bar`·`#caption`·`#source`, Remotion은 `src/parts/*.tsx`다. 세팅 스킬은 공용 부품을 따로 만들어 두지 않는다. `_채널공용/부품/`은 **비어 있는 자리**로만 만들어지고, 회차를 만들다가 여러 회차가 같이 쓰는 요소(포인트 문구·CTA 등)가 생겼을 때 2단계에서 그리로 떼어낸다. 떼어낸 뒤부터는 회차가 복사 대신 참조만 한다.

## 레퍼런스 모으기

세팅 스킬은 레퍼런스를 모으고 기록하는 데까지만 한다. 실제 다운로드·분석은 `watch` 모듈이 설치돼 있고 사용자가 원할 때만 세팅 끝에 이어서 하거나, 아니면 2단계 스킬의 "레퍼런스·스타일 분석" 단계에서 한다.

고르는 기준: 포맷이 같은 영상, 영상 유형이 같은 영상, 자막·제목·컷 템포 중 하나라도 방향이 뚜렷한 영상, 1~3개(많을수록 좋은 게 아니라 방향이 한쪽으로 모이는 게 중요하다).

세팅이 만드는 것:
- `<채널>/02_기획과자막/스타일레퍼런스/레퍼런스_목록.md` — 영상별 URL 또는 경로, 마음에 드는 점, 상태(미분석/분석 완료).
- `<채널>/02_기획과자막/스타일레퍼런스/레퍼런스_모으는_법.md` — 위 기준과, 나중에 가져오기로 넘어간 사람이 할 일.
- `스타일_라이브러리/06_참고영상/_양식/` — 분석 5종 세트 양식(`원본정보.md`, `구조분석.md`, `스타일분석.md`, `적용규칙.md`, `metadata.json`)과 `캡처/` 자리.

분석 문서에서는 **관찰한 것**(레퍼런스 영상에서 실제로 본 것)과 **채택한 규칙**(우리 채널이 쓰기로 정한 값)을 구분해서 적는다. `적용규칙.md`의 표가 이 둘을 나란히 놓고 `frame.md` 키로 연결한다. 폰트처럼 화면만 봐서는 확정할 수 없는 값은 "추정"이라고 적는다. 레퍼런스 영상의 화면·소리를 우리 영상에 그대로 가져다 쓰지 않는다.

## canvas는 채널 포맷을 따른다

`frame.md`의 `canvas`(width/height/fps)는 채널이 고른 포맷을 그대로 따른다 — 9:16 쇼츠는 1080×1920, 16:9 롱폼은 1920×1080, fps는 30 고정이다. 스캐폴드가 채널을 만들 때 이 값을 채널 포맷에 맞춰 자동으로 써 넣으므로, `frame.md`를 손으로 바꿀 때도 채널 포맷과 어긋나지 않게 맞춘다. 어긋나면 스모크 테스트가 렌더 전에 오류로 막는다.
