# 자주 겪는 문제

shorts 파일럿과 이 스킬을 만드는 동안 실제로 겪은 문제를 증상 → 원인 → 해결 순서로 모았다. 각 모듈 문서의 "자주 막히는 곳"이 여기를 가리킨다.

## 1. 렌더가 "Navigation timeout"으로 멈춘다

- **증상**: `hyperframes check`나 `render`가 "Navigation timeout"을 내며 멈춘다.
- **원인**: macOS 기본 오디오 출력 장치가 USB 마이크처럼 소리를 낼 수 없는 장치로 잡혀 있으면, 헤드리스 크롬의 WebAudio 초기화 자체가 멈춘다.
- **해결**: macOS에서는 먼저 기본 오디오 출력 장치를 확인한다. 그다음 `<workspace>/도구/chrome-noaudio.py`(오디오 출력을 끄는 크롬 래퍼)를 적용한다. 영상의 소리는 ffmpeg가 따로 합치므로 잃는 것이 없다.

```
HARNESS_CHROME=<`npx hyperframes browser path` 결과>
HYPERFRAMES_BROWSER_PATH=<workspace>/도구/chrome-noaudio.py
```

두 환경변수를 설정하고 `check`/`render`를 다시 실행한다.

## 2. 남은 크롬 프로세스가 다음 렌더를 방해한다

- **증상**: 다음 렌더가 이상하게 느리거나 포트 충돌로 실패한다.
- **원인**: `hyperframes preview` 서버나 `chrome-headless-shell` 프로세스가 이전 실행에서 종료되지 않고 남아 있다.
- **해결**: 렌더나 확인 작업이 끝나면 남은 `hyperframes preview` 서버와 `chrome-headless-shell` 프로세스를 찾아 종료한다. 새로 시작하기 전에 한 번 정리하는 습관을 들인다.

## 3. 모델 다운로드가 멈춘다

- **증상**: TTS나 전사 모델을 내려받는 도중 진행이 멈춘 채로 끝나지 않는다.
- **원인**: 허깅페이스 다운로드 가속 경로(Xet)가 환경에 따라 멈추는 경우가 있다.
- **해결**: 환경변수 `HF_HUB_DISABLE_XET=1`을 설정하고 한 번 재시도한다. 로컬 목소리 복제 모듈의 다운로드 단계는 이 환경변수를 이미 설정해 두었지만, 수동으로 다시 받을 때도 같은 값을 쓴다.

## 4. TTS 환경을 기존 파이썬과 섞어 쓴다

- **증상**: TTS를 설치한 뒤 다른 파이썬 스크립트가 이상하게 동작하거나, 반대로 TTS가 깨진다.
- **원인**: `mlx-audio` 같은 TTS 패키지는 무겁고 특정 버전에 민감해서, 도구 가상환경 전체와 충돌할 수 있다.
- **해결**: TTS는 항상 `<workspace>/도구/tts/.venv`라는 자신만의 가상환경에 설치하고 다른 목적(스타일 검사, CapCut 내보내기 등)의 가상환경과 섞지 않는다.

## 5. 회차 폴더에서 명령을 실행하면 상태가 흩어진다

- **증상**: 로그·결과 파일이 예상한 곳에 없고 여기저기 흩어진다.
- **원인**: `harness.config.json`과 `도구/logs/` 같은 상태 폴더는 모두 작업 공간 루트를 기준으로 한 상대 경로다. 회차 폴더나 프로젝트 폴더 안에서 스크립트를 실행하면 그 폴더 밑에 새로 만들어진다.
- **해결**: 모든 스크립트는 작업 공간 루트에서 실행하거나, `--workspace`(또는 첫 위치 인자)로 작업 공간 경로를 명시한다. 현재 디렉터리에 의존하지 않는다.

## 6. transform이 있는 SVG `<g>`에 GSAP 트윈을 걸면 값이 덮어써진다

- **증상**: SVG 요소를 GSAP으로 움직이면 처음 위치가 무시되거나 애니메이션이 튄다.
- **원인**: 이미 `transform` 속성(위치 지정용)이 있는 `<g>`에 GSAP 트윈을 직접 걸면, GSAP이 그 transform 값을 자신의 계산으로 덮어써 버린다.
- **해결**: 위치를 담당하는 바깥쪽 `<g transform="...">`와, 애니메이션을 담당하는 안쪽 `<g>`를 분리한다. GSAP 트윈은 안쪽 `<g>`에만 건다.

## 7. HDR/H.265 원본을 쓰면 색이 틀어진다

- **증상**: 원본 촬영본을 배경으로 쓰면 결과 영상의 색이 원본과 다르게 보인다(과채도, 밝기 차이 등).
- **원인**: HDR로 촬영되었거나 H.265(HEVC)로 인코딩된 원본은 표준 SDR 색공간을 가정하는 파이프라인에서 색이 어긋날 수 있다.
- **해결**: 원본이 HDR/H.265인지 먼저 확인하고, 필요하면 SDR·H.264로 변환한 사본을 만들어 편집에 쓴다. 최종 결과물의 색을 원본과 눈으로 비교해 확인한다.

## 8. 에이전트는 소리를 듣지 못한다

- **증상**: 기술적으로는 통과했는데 실제로 들어보면 음질이 이상하거나 발음이 어색하다.
- **원인**: 에이전트가 확인할 수 있는 것은 오디오 스트림이 존재하는지, 길이가 맞는지 같은 기술적 사실뿐이다. 소리가 자연스럽게 들리는지는 파형이나 로그로 알 수 없다.
- **해결**: 기술 검사 통과와 청취 확인을 구분해서 기록한다. 실제로 소리가 자연스러운지 청취 확인은 항상 사람이 직접 해야 하는 몫이고, 하지 않았으면 미확인으로 남긴다.

## 9. TTS 결과가 실행할 때마다 톤이 달라진다

- **증상**: 같은 대본인데 생성할 때마다 목소리 톤·속도가 조금씩 다르게 나온다.
- **원인**: 목소리 복제 TTS는 생성 자체에 무작위성이 있어, 참고 음성·설정이 같아도 결과가 완전히 똑같지 않다.
- **해결**: 채널마다 기준이 되는 참고 음성 파일, 생성 설정(문단 단위 생성 여부, 언어 코드 등), 후처리 값(속도·피치)을 한 묶음으로 정해 고정해서 쓴다. 값을 바꿔야 하면 그 사실을 기록하고 이후 회차에도 같은 값을 적용한다.

## 10. 없는 폰트 파일을 `url()`로 가리키면 스타일 검사가 실패한다

- **증상**: `hyperframes check`가 폰트 관련 오류로 실패한다.
- **원인**: `@font-face`의 `src`가 실제로 존재하지 않는 폰트 파일을 `url(...)`로 가리키고 있다.
- **해결**: 프로젝트에 폰트 파일이 아직 없으면 `local(...)` 폴백만 남겨 시스템 폰트로 대체되게 하거나, 실제 폰트 파일을 연결한 뒤에 `url(...)`을 추가한다. 폰트를 연결하는 방법은 각 회차 템플릿의 `넣는_방법.md`를 따른다.

## 11. 녹음 폴더에 `.DS_Store`가 섞여 있다

- **증상**: 참고 녹음이나 대본을 자동으로 찾는 단계가 엉뚱한 파일을 고르거나 아무것도 못 찾는다.
- **원인**: macOS가 폴더마다 남기는 `.DS_Store` 같은 숨김 파일이 후보 목록에 섞여 정렬 순서를 흐트러뜨릴 수 있다.
- **해결**: 녹음 폴더에는 실제 음성 파일과 대본 텍스트만 남긴다. 점(`.`)으로 시작하는 파일은 지우거나 무시되는지 확인한다.

## 12. macOS CapCut 초안 파일명이 다르다

- **증상**: `pycapcut`으로 만든 초안이 CapCut 앱의 실제 초안과 구조가 달라 보인다.
- **원인**: macOS에서 CapCut 앱이 직접 만드는 초안은 `draft_info.json`을 쓰는데, `pycapcut`은 `draft_content.json`을 쓴다. 파일명 자체가 다르다.
- **해결**: 두 파일명이 다르다는 것을 전제로 다룬다. CapCut 9.4.0(macOS)이 `pycapcut` 초안을 실제로 여는지는 아직 실기 확인 대기 상태이므로, 열린다고 단정하지 말고 안 열리면 수동 묶음(SRT + 컷 목록 + 가져오는 방법) 대안을 안내한다.

## 13. `frame.md`의 canvas가 채널 포맷과 어긋난다

- **증상**: 스모크 테스트가 렌더 전에 canvas 오류로 막힌다.
- **원인**: `frame.md` 머리말의 `canvas`(width/height)가 그 채널의 포맷(9:16 또는 16:9)에 맞는 해상도와 다르다.
- **해결**: 채널 포맷이 9:16이면 1080×1920, 16:9면 1920×1080으로 `frame.md`의 `canvas` 값을 맞춘다. 채널을 새로 스캐폴드하면 이 값은 자동으로 맞춰지므로, 손으로 고친 뒤에는 반드시 다시 확인한다.
- **이미 만든 채널의 포맷을 바꿨다면 세 곳을 같이 고친다.** 스캐폴드는 이미 있는 파일을 덮지 않으므로(그래야 손댄 회차 템플릿이 날아가지 않는다), `config_tool.py set … channels.N.format`으로 포맷만 바꾸고 `scaffold.py`를 다시 돌려도 회차 템플릿은 예전 해상도로 남는다. ① `frame.md`의 `canvas`, ② `회차템플릿/index.html`의 루트 `data-width`·`data-height`와 `<meta name="viewport">`의 `width`·`height`, ③ Remotion을 쓰면 `회차템플릿-remotion/src/theme.ts`의 `canvas`. 셋을 맞춘 뒤 스모크 테스트를 다시 돌린다. 세 값이 어긋나면 스모크가 해상도 검증에서 막힌다.

## 14. 도구가 없거나 설치가 빠졌다

- **증상**: `도구/` 아래 있어야 할 스크립트나 가상환경이 없다.
- **원인**: 스캐폴드가 복사하는 도구 파일(`chrome-noaudio.py`, `style/check_style.py` 등)이 빠졌거나, `install_module.py run`으로 설치해야 하는 가상환경·모델이 아직 안 만들어졌다.
- **해결**: 도구 파일이 빠졌으면 `python3 "${SKILL_DIR}/scripts/scaffold.py" "<workspace>"`를 다시 실행한다. scaffold는 멱등이라 이미 있는 파일은 절대 덮어쓰지 않고 없는 것만 채운다. 가상환경·모델 같은 설치 자체가 빠졌으면 `python3 "${SKILL_DIR}/scripts/install_module.py" run "<workspace>" <모듈>`로 그 모듈을 다시 설치한다.
