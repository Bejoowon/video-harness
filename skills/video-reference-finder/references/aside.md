# Aside로 탐색 맡기기

Aside는 사용자의 **로그인된 브라우저**를 움직이는 바깥 CLI다. `aside exec`는 Aside 브라우저 안의 에이전트에게 일을 통째로 맡기는 것이라, 하위 에이전트를 부르는 것과 같다. 그래서 무엇을 시켰는지, 지금 무엇을 하고 있는지를 사용자가 계속 알 수 있어야 한다.

확인한 버전: Aside CLI 1.26 (macOS에서 이 용도로 한 번 실제로 돌려 봤다 — 후보 8개를 JSON 배열로 돌려줬고 모두 실존하는 주소였다). 한 번 돌려 본 것이라 늘 그렇다고 볼 수는 없다. 결과가 이 문서와 다르면 그대로 알린다.

실제로 겪은 것: 결과가 ```json 코드 블록에 담겨 오고, 진행 중에는 훑어본 영상 목록이 계속 흘러나온다. 그래서 마지막 코드 블록의 배열만 뽑아 `verify`에 넘긴다. 8개짜리 탐색에 5분쯤 걸렸다.

## 시작하기 전에

1. 무엇을 시킬지(4절 지시문)를 사용자에게 보여 준다.
2. **몇 분이 걸리고 사용자의 Aside 사용량이 든다**고 알린다.
3. 동의를 받고 시작한다. 동의 없이 시작하지 않는다.

```
aside exec "<4절에서 만든 지시문>"
```

- 권한은 기본값(guard)만 쓴다. 권한을 올리는 옵션은 쓰지 않는다.
- 지시문에는 보기 전용 규칙이 이미 들어 있다. 지시문을 손으로 줄이지 않는다.

## 도는 동안

- 실행을 지켜보며 **약 60초마다** 한 줄로 알린다: 지금 어느 플랫폼을 보고 있는지, 후보를 몇 개 모았는지.
- 더 시킬 말이 생기면 세션을 이어 간다.

```
aside session resume <세션 id> "<더 시킬 말>"
```

- **10분**을 넘기면 계속할지 멈출지 **묻는다**. 혼자 정하지 않는다.

```
aside session stop <세션 id>
```

## 끝난 뒤

결과는 JSON 배열이면 그대로, 아니면 글 그대로 파일에 저장하고 재확인(`verify`)으로 넘긴다. **Aside가 돌려준 목록은 주장일 뿐이다.** 재확인을 거치기 전에는 어떤 후보도 `확인됨`이라고 말하지 않는다.

## 실패했을 때

| 무슨 일 | 할 일 |
|---|---|
| 명령이 오류로 끝난다 | 오류 문장을 그대로 사용자에게 보여 주고, 다른 수단으로 바꿀지 묻는다 |
| 빈 결과가 온다 | 조건이 좁았는지 함께 보고, 플랫폼·분야를 넓혀 다시 할지 묻는다 |
| 로그인 화면에서 막힌다 | 그 플랫폼은 건너뛰고 건너뛰었다고 알린다. 로그인 정보를 입력하지 않는다 |
| 10분이 넘도록 끝나지 않는다 | 멈출지 묻고, 멈추기로 하면 세션을 멈춘 뒤 그때까지 모은 것만 가지고 간다 |
| Aside가 설치돼 있지 않다 | 애초에 이 길로 오지 않는다. SKILL.md 3절의 다음 수단으로 간다 |

어느 경우에도 **조용히 넘어가지 않는다.** 실패를 감추고 다른 결과를 내놓으면, 사용자는 찾아본 적 없는 목록을 찾아본 것으로 믿게 된다.

## 하지 않을 것

- 구독·좋아요·댓글·팔로우·메시지·저장 같은 **바꾸는 동작**을 시키지 않는다.
- 로그인·회원가입·결제 화면을 지나가게 하지 않는다.
- 파일을 내려받게 하지 않는다.
- 사용자의 다른 탭이나 개인 정보를 읽어 오게 하지 않는다. 필요한 것은 공개된 영상·채널 페이지뿐이다.
