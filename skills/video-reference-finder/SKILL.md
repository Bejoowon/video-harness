# 레퍼런스 찾기

닮고 싶은 영상·채널을 찾아 주는 스킬이다. **찾기까지만** 한다 — 찾은 영상의 스타일 분석은 세팅 스킬의 `watch` 모듈이 맡고, 영상 내려받기·주제 조사·업로드는 이 스킬이 하지 않는다.

## 대화 규칙

이 규칙이 아래 모든 절보다 우선한다. 어긋나 보이는 문장이 있으면 여기를 따른다.

1. **질문을 하면 거기서 멈추고 사용자의 답을 기다린다.** 답이 오기 전에는 다음 질문으로도, 탐색으로도, 기록으로도 넘어가지 않는다.
2. **대신 답하거나 대신 고르지 않는다.** 마지막에 고르는 사람은 사용자다.
3. **추측해서 채우지 않는다.** 사용자가 이미 말한 것은 되짚어 확인만 하고, 말하지 않은 것은 묻는다.
4. **사용자에게 물을 수 없는 환경(비대화형 실행)이면 찾지 않는다.** 물어야 할 질문 목록만 내놓고 멈춘다.
5. **확인하지 않은 것을 확인했다고 하지 않는다.** 다른 에이전트가 가져온 목록은 주장일 뿐이다.

## 명령 규칙

- `SKILL_DIR` — 지금 읽고 있는 이 SKILL.md가 들어 있는 폴더의 절대경로다. 설치 위치는 사람마다 다르므로 이 파일을 읽은 경로에서 파일 이름만 뺀 값을 쓴다.
- 예시의 `${SKILL_DIR}`와 꺾쇠 자리표시자는 셸 변수로 두지 말고 실제 값으로 바꿔서 실행한다. 경로에 공백이 있을 수 있으니 언제나 큰따옴표로 감싼다.
- 실행 형태: `python3 "${SKILL_DIR}/scripts/finder_tool.py" detect "<폴더>"`. Windows에서는 `python3` 대신 `python`을 쓴다.
- 이 스크립트는 JSON이나 한국어 표로 답한다. 결과를 그대로 쏟지 말고 필요한 줄만 옮긴다.

## 1. 시작

지금 대화가 열려 있는 폴더를 `<폴더>`로 삼아 먼저 확인한다.

```
python3 "${SKILL_DIR}/scripts/finder_tool.py" detect "<폴더>"
```

읽을 값: `mode`(`workspace`면 세팅된 작업 공간, `standalone`이면 그냥 폴더), `channels`(채널 목록과 이미 적힌 방향), `aside`(Aside CLI가 있는지), `config_tool`(세팅 스킬의 기록 도구 경로, 없으면 `null`), `watch_installed`(레퍼런스 분석 모듈이 켜져 있는지).

`config_error`가 있으면 설정 파일이 깨진 것이다. 그대로 알리고, 고치기 전에는 기록하지 않는다.

## 2. 짧은 인터뷰

한 번에 하나씩 묻는다. 답을 받기 전에 다음으로 넘어가지 않는다.

**작업 공간 모드** — 어느 채널의 레퍼런스인지 고르게 하고, `detect`가 알려 준 방향 중 **비어 있는 것만** 묻는다. 이미 있는 값은 "이 채널은 ○○ 대상이라고 적혀 있네요, 맞나요?"처럼 되짚어 확인만 한다. 찾을 곳의 기본값은 채널의 `platforms` 답에서 고르고, 사용자가 바꿀 수 있다.

**단독 모드** — 여섯 가지를 묻는다: 분야 · 누가 보는지 · 세로(`9:16`)인지 가로(`16:9`)인지 · 촬영본으로 만드는지 대본부터 쓰는지 · 어디에 올릴지(유튜브·인스타그램·틱톡) · 특히 보고 싶은 것.

**두 모드 모두 매번 묻는 한 가지**: "이번에 **특히 보고 싶은** 게 뭐예요?" — 자막 / 구성 / 컷 템포 / 말투 / 썸네일 / 제목 / 전부 중에서 고르게 한다.

선택으로 더 물어도 좋은 두 가지: 피하고 싶은 것(예: 자극적인 썸네일, 광고 위주 채널), 이미 아는 채널(그것과 비슷한 곳을 찾는다).

## 3. 수단 정하기

위에서부터 처음 맞는 조건 하나만 적용한다.

| 조건 | 할 일 |
|---|---|
| `detect`의 `aside.found`가 참 | 4절 지시문을 만들고 5절 Aside로 맡긴다. 사용자가 원하지 않으면 다음 줄로 간다 |
| 웹을 검색하거나 페이지를 열 수 있는 수단이 있다 | 같은 지시문대로 에이전트가 직접 찾는다 |
| 둘 다 없다 | 없다고 그대로 말하고, `judging.md`의 고르는 기준을 보여 주며 사용자에게 링크를 받는다 |

셋째 줄에서 **찾아본 척하지 않는다.** 주소·채널 이름·숫자를 지어내지 않는다.

## 4. 탐색 지시문 만들기

인터뷰 답을 JSON 파일로 적고 지시문을 조립한다. 키는 `field` · `audience` · `format` · `workflow`(선택) · `platforms` · `focus` · `avoid`(선택) · `similar_to`(선택)다.

```
python3 "${SKILL_DIR}/scripts/finder_tool.py" brief --answers "<답 파일>"
```

후보는 기본 8개다. 더 적게·많이 받으려면 `--count 5`처럼 준다. 출력은 사람이 읽을 수 있는 글이고, 그 안에 찾을 곳·포맷·후보마다 돌려줄 항목·보기 전용 규칙·결과 형식이 들어 있다. 답이 올바르지 않으면 무엇이 틀렸는지 한국어로 알려 주고 지시문을 만들지 않는다.

## 5. 탐색 맡기기

### Aside가 있을 때

시작 전에 먼저 알린다: **몇 분이 걸리고, 사용자의 Aside 사용량이 든다.** 동의를 받고 시작한다.

```
aside exec "<4절에서 만든 지시문>"
```

- 실행을 지켜보며 **약 60초마다** 무엇을 하고 있는지 한 줄로 알린다.
- 이어서 시킬 말이 있으면 `aside session resume <세션 id> "<더 시킬 말>"`.
- **10분**을 넘기면 계속할지 멈출지 묻는다. 멈추기는 `aside session stop <세션 id>`.
- 권한은 기본값(guard)만 쓴다. `--permission full-access`는 쓰지 않는다.
- Aside는 사용자의 로그인된 브라우저를 움직인다. 아래 "안전 규칙"을 그대로 지킨다.

자세한 내용과 실패했을 때 할 일은 `references/aside.md`에 있다.

### Aside가 없을 때

웹을 검색하거나 페이지를 열 수 있는 수단으로 같은 지시문대로 직접 찾는다. 규칙도 같다 — 보기만 하고, 실제로 연 페이지에서 본 것만 적는다.

### 실패했을 때

Aside가 실패하거나 빈 결과를 주면 **이유를 그대로 알리고** 다른 수단으로 바꿀지 묻는다. **조용히 넘어가지 않는다.**

## 6. 재확인

찾아 온 결과를 파일로 저장하고 확인한다. JSON 배열이 아니어도 된다 — 글에서 주소를 뽑아 `설명 없음`으로 표시한다.

```
python3 "${SKILL_DIR}/scripts/finder_tool.py" verify "<후보 파일>" --table
```

상태는 네 가지다.

| 상태 | 뜻 |
|---|---|
| `확인됨` | 주소가 실제로 열렸다. 제목·채널명을 실제 값으로 덮어썼다 |
| `없는 주소` | 열리지 않는다. 목록에서 뺐다 |
| `직접 확인 필요` | 자동으로 확인할 수 없다(인스타그램 등). 가짜라는 뜻이 아니다 |
| `확인 실패` | 네트워크·서버 문제로 확인하지 못했다. 빼지 않고 표시만 한다 |

같은 영상·채널을 가리키는 주소는 하나로 합쳐진다. 네트워크가 없으면 전부 `확인 실패`로 남으니, 사용자에게 직접 열어 보라고 한다.

## 7. 고르기 — 여기서 멈춘다

표를 그대로 보여 주고 **사용자가 고르게 한다**. 대신 고르지 않는다. 답이 오기 전에는 8절로 넘어가지 않는다.

- 1~3개를 고르고, 각각 **어디가 마음에 드는지** 한 줄로 받는다. 자막 / 제목 / 컷 템포 / 색감 / 효과음·BGM / 구성 중에서 고르게 하면 대답하기 쉽다.
- 마음에 드는 게 없으면 무엇이 달랐는지 묻고 4절부터 다시 한다.
- 후보가 **3개 미만**이면 조건을 넓힐지(다른 플랫폼, 인접 분야) 먼저 묻는다.
- 고르는 기준을 함께 보여 줄 때는 `references/judging.md`를 읽는다.

## 8. 기록

### 작업 공간 모드

설정의 기록 창구는 세팅 스킬의 `config_tool.py` 하나다. `detect`가 알려 준 경로를 그대로 쓴다.

```
python3 "<config_tool 경로>" add-reference "<ws>" --channel <채널 id> --reference "URL::자막이 크고 가운데에 겹친다"
```

`--reference`는 고른 개수만큼 여러 번 준다. 이미 적힌 주소는 건너뛴다. 저장이 끝나면 그 채널의 `02_기획과자막/스타일레퍼런스/레퍼런스_목록.md`에 **없는 줄만** `미분석`으로 덧붙는다. 사용자가 고쳐 놓은 줄은 건드리지 않는다. 채널 폴더가 아직 없으면 설정만 바뀌고 그렇다고 알려 준다.

### 단독 모드

고른 목록을 JSON 배열(`url` · `likes` · `what`(선택) · `status`(선택))로 적고 기록한다.

```
python3 "${SKILL_DIR}/scripts/finder_tool.py" record --standalone "<폴더>" --picked "<고른 목록 파일>"
```

지금 폴더에 `레퍼런스_후보.md`를 만든다. 이미 있으면 표 끝에 덧붙이고, 이미 적힌 주소는 건너뛴다.

## 9. 다음

- `detect`의 `watch_installed`가 참이면 "바로 분석할까요?"를 묻는다.
- 아니면 어디에 기록했는지만 알리고 끝낸다. 레퍼런스는 `미분석`으로 남는다.

## 안전 규칙

탐색을 맡길 때도 직접 찾을 때도 똑같이 지킨다. 지시문에도 그대로 들어간다.

- **보기만 한다.** 구독·좋아요·댓글·팔로우·메시지·저장을 하지 않는다.
- 로그인 정보·비밀번호를 입력하지 않는다. 로그인 화면이 나오면 그 플랫폼은 건너뛰고 그렇다고 알린다.
- 아무것도 내려받지 않는다.
- 구독자·조회수 같은 숫자는 페이지에서 직접 본 것만 적는다. 못 봤으면 아예 쓰지 않는다. 채널·주소·숫자를 **지어내지 않는다.**
- 레퍼런스는 **분석용**이다. 레퍼런스 영상의 화면·소리를 내 영상에 가져다 쓰지 않는다.
- 재확인을 거치지 않은 후보를 `확인됨`이라고 말하지 않는다.

## 말하는 법

- 한국어로, 쉬운 말로 쓴다. 긴 JSON을 그대로 붙여넣지 않는다.
- 확인하지 못한 것은 "미확인"이라고 말한다. 인스타그램 주소는 자동으로 확인할 수 없다.
- 실패를 감추지 않는다. 실패한 수단과 이유를 그대로 알린다.
